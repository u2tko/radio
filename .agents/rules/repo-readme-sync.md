# リポジトリ全体：新規ファイル作成時の `README.md`・参照先同期ルール

本リポジトリ配下で新しいドキュメント・分析ノート・スクリプト・設定ファイル・ディレクトリを作成（または改名・削除）した際は、後から別の会話でAIや人間が迷わず発見・参照できるよう、以下の基準で索引を更新する。

---

## 1. 更新が必要な対象と反映先

1. **分析レポート・整理ノート・設計書・補助資料・スクリプト等**
   - 格納例：`hyogo/analysis/`、`hyogo/kaiken/analysis/`、`hyogo/kaiken/external/`、`research/`、新規の解説・手順ドキュメントなど。
   - **反映先**：
     - 同ディレクトリに `README.md` がある場合は、その `README.md` にファイル名・相対リンク・概要を追記する。
     - 同ディレクトリに `README.md` がない場合は、新規に `README.md` を作成するか、直近の親ディレクトリの `README.md`（例：`hyogo/README.md`）へ追記する。
2. **新規サブディレクトリ（フォルダ）を作成した場合**
   - 原則として、そのディレクトリ直下に `README.md` を作成して目的と収録構成を明記し、あわせて親ディレクトリの `README.md` が存在する場合は構成一覧へ追記する。
3. **AIに毎回の作業で参照させたい基盤資料・ルール・スキルを新設・改名した場合**
   - 該当の `README.md` の更新に加え、関連する `.agents/rules/*.md` および `.agents/skills/*/SKILL.md` の参照先にもファイル名を追記する。
4. **定例・日次で継続蓄積されるデータファイルの例外（適切な集計先へ反映）**
   - 毎回の個別追記が運用負荷や自動スクリプトとの競合を招く以下のファイルは、作成ごとの `README.md` 手動追記は不要とし、所定の索引・棚卸し先で管理する：
     - `hyogo/YYYY-MM/YYYYMMDD.md`（日次配信台本）：月次・期間更新時に `hyogo-archive-analysis` スキルに沿って `hyogo/analysis/` の棚卸しレポートへ反映する。
     - `hyogo/kaiken/2026/YYYY-MM-DD.md`（公式会見録）：`hyogo/kaiken/scripts/convert_kaiken.py` による `hyogo/kaiken/2026/README.md`・`index.json` の同期を優先する（手動追加時は同 `README.md` へ追記）。
     - `research/YYYY-MM-DD_*.md`（Grok等調査メモ）：`research/README.md` の規約に従って配置し、継続参照するまとめメモを作成した場合に `research/README.md` へ追記する。
     - 別企画の日次原稿（ルート配下の `YYYY-MM/*.md` 等）：日次原稿は対象外とし、共通テンプレートやガイドを新設した場合のみ該当 `README.md` 等へ記載する。

---

## 2. 記述・検証ルール

- **ポータブルな相対リンクを使う**：ファイル内のリンクは `./file.md` や `../dir/file.md` のような相対パスのみを使用し、ローカルPC固有の絶対パス（`C:\Users\...` 等）は書かない。
- **追記後にリンク実在を検証する**：`README.md` やルールを更新したら、記載したすべての相対パスが実在するファイルに解決することを確認する。
- **報告時の明示**：新規ファイル作成時に同期した `README.md` やルールファイルがあれば、ユーザーへの完了報告でリンクを添えて伝える。
