# `#兵庫クリーンラジオ` 台本制作・壁打ちワークフロー

このスキルは、`hyogo/` 配下の新しい配信原稿を「ネタ出し・壁打ち → 構成確定 → ドラフト執筆 → 読み上げ＆リスク点検」の順で再現性高く仕上げるための手順を定める。

台本の書式ひな形は [script-template.md](./resources/script-template.md) を参照する。

---

## ステップ1：素材確認と過去回チェック

1. ユーザーから提供された素材（会見書き起こし、報道、公式資料、SNS投稿、配信者の感想・主張）を整理し、以下を仕分ける：
   - 確認済みの一次資料・公式記録
   - 報道・書き起こしベースの事実（公式記録待ちのもの）
   - 未確認情報・SNS上の反応（根拠に使わないもの）
   - 配信者の見立て・主張
2. `hyogo/analysis/` の最新棚卸しレポートや直近の `hyogo/YYYY-MM/` を確認し、**関連する過去回**（相互参照できる回・論点が重なる回）を洗い出す。

## ステップ2：壁打ち（論点の核づくりと弱点点検）

いきなり台本を書かず、まず以下を簡潔に提示してユーザーと合意を取る（ユーザーが「すぐ台本を書いて」と明示した場合のみステップ3へ直行する）：

1. **論理・事実チェック**: 飛躍、因果の断定、過度な形容、ソース不足がないか。
2. **先出しすべき前提・異論**: 批判対象側に有利な事実や想定反論（先に認めておくことで論証を強くするポイント）。
3. **論点の核（対比軸）**: この回を一言で表す対比構造（例：「Aには検証するのに、Bには『適切』で終わらせる」「告訴は個人、排除は県」など）。
4. **4章構成案とタイトル案（2〜3案）**:
   - 第1章：何が起きたか（事実・発言の整理）
   - 第2章：核心の矛盾・対比①（前提や異論の留保も含める）
   - 第3章：構造の掘り下げ・対比②（過去発言・別案件・公的理念との接続）
   - 第4章：この問題が持つ意味（県政・県民にとっての論点）

## ステップ3：ドラフト執筆（11月完成形フォーマット）

[script-template.md](./resources/script-template.md) に厳密に従って原稿を作成する。

- **文字数目安**: 空白除き **3,200〜3,800字**（約9〜11分）。
- **文体ルール**:
  - プレーンな読み上げ文体（本文中の `**太字**`、`---`、`［事実］` などの記号タグは入れない）。
  - 「番組」ではなく「配信」を使う。
  - 短文・体言止め・問いかけを適度に交え、耳で聞いてリズムよく追える文章にする。
  - 感情的な罵倒は避けつつ、配信者の自然な違和感や問題意識が伝わるトーンを保つ。
- **※参考資料の記載**:
  - 出典名・日付・引用した発言の対応を明記する。
  - 書き起こし依拠・未確認事項・配信者の見立て箇所・過去回参照・壁打ち経緯を省略せず記録する。

## ステップ4：最終チェックとファイル保存

ドラフト提示（または保存）前に、以下を必ず点検し、問題があれば修正または注意点としてユーザーに伝える：

- [ ] 1行目が `#兵庫県政正常化 #兵庫クリーンラジオ タイトル`（`【】`なし・先頭スペースなし）になっているか
- [ ] 冒頭リードでテーマと結論（問いの核）が先に示されているか
- [ ] NGライン（人格断定・私人特定・死因断定・私的情報再現・未確認情報の事実扱い）に触れていないか
- [ ] 名誉毀損リスクが高い断定表現がないか（ある場合は表現案を添えて警告する）
- [ ] 文字数が目安（約3,200〜3,800字）に収まっているか
- [ ] 保存先を求められた場合、`hyogo/YYYY-MM/YYYYMMDD.md`（既存があれば末尾に連番）へUTF-8で保存し、文字数を報告する
