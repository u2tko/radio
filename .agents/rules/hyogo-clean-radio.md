# `#兵庫クリーンラジオ` プロジェクト専用ルール

本ルールは、このリポジトリの `hyogo/` 配下（`#兵庫クリーンラジオ`）に関する分析・壁打ち・原稿作成・校正を行う際に適用する（他フォルダの別企画を扱う場合は適用しない）。

---

## 1. 番組の基本スタンスと扱う範囲

- **番組名**: `#兵庫クリーンラジオ`（※本文中で「番組」という語は使わず、原則「配信」を使う）
- **基本立場**: 兵庫県政（知事および周辺議員・支援者の公的言動・政策・会見運営・説明責任）を、一次資料と事実の並びに基づいて検証・論評する批判的スタンス。
- **主な対象**:
  - 政策方針、予算、財源、事業実績、公務の優先順位・出席状況
  - 定例会見・議会答弁・公式SNS発信の整合性と説明責任
  - 記者会見運営・報道の自由・市民の抗議活動への公的対応
  - 告発文書問題・第三者委員会・百条委員会の公的認定と知事説明の対比
- **扱わないもの（厳守するNGライン）**:
  - 人格・性格・内心の断定（推測する場合は必ず「私の見立てでは」「〜のように見える」等と明示する）
  - 家族・一般職員・一般支持者の個人特定や私人攻撃、動員制裁
  - 故人の死因の断定、私的情報の再現・詮索
  - 裏付けのない「不正リスト」や未確認情報の事実扱い

## 2. 事実検証と留保の規律（11月完成形の基準）

目標は「反論されないこと」ではなく **「検証に耐えること」** とする。

1. **情報階層の明確な区別**（本文では記号タグ `［事実］` 等を使わず、自然な話し言葉で言い分ける）:
   - 一次資料・事実（公式議事録、会見書き起こし、予算書、公的統計、原文引用）
   - 公式説明（県・知事・当事者がそう述べていること）
   - 外部指摘・報道（第三者委、百条委、監査、報道機関の記事）
   - 配信者の見立て・主張（「私は〜と考えます」「私の見立てでは〜」）
2. **フェアな前提・異論の先出し留保**:
   - 批判対象側に不利にならない前提事実や反対論がある場合、あえて本文の前半〜中盤で先に認めたうえで本論へ入る（例：第三者委報告は裁判判決ではない、代理出席自体は珍しくない、支持率の回復推移自体は事実、抗議・発言側のライン越えは認める等）。
3. **未確認情報・ソース制約の透明化**:
   - 未確認のSNS情報や切り抜き動画は事実と断定せず、「仮定」「推測」「未確認のため不採用」と明記する。
   - SNS検索（Grok/Threads等）や反応紹介は「受け止めの紹介」にとどめ、事実の根拠には使わない。
   - 県公式の会見録が未公開の段階では、報道・書き起こし・視聴確認に基づく旨を `※参考資料` に注記する。
4. **対比構造による検証**:
   - 単発の印象論ではなく、「過去の知事発言 vs 現在の発言」「他案件での対応 vs 自身に関わる案件での対応」「公的計画・理念 vs 実際の行動」を並置して構造を浮かび上がらせる。

## 3. 最新台本フォーマット（2026年11月完成形）

`hyogo/outline/` にある初期テンプレート（9月期）よりも、以下の **11月完成形** を現行標準として優先する。

- **ファイル配置・命名**: `hyogo/YYYY-MM/YYYYMMDD.md`（同日複数本の場合は `YYYYMMDD2.md` 等）
- **目安文字数**: 空白除き **約3,200〜3,800字**（読み上げ約9〜11分）
- **プレーン文体**: 読み上げやすさ優先のため、本文中の太字強調（`**...**`）、章間の水平線（`---`）、記号タグ（`［事実］` 等）、タイトルの `【】` は使わない。
- **標準構成**:
  1. **1行目（告知兼タイトル）**: `#兵庫県政正常化 #兵庫クリーンラジオ タイトル`（先頭スペースなし）
  2. **定型オープニング**:
     `みなさん、こんばんは。兵庫クリーンラジオ、M月D日、X曜日の配信です。この配信では、兵庫県政の正常化を願って、私が思ったことを中心にお話ししています。`
  3. **結論先行リード**: 今日のテーマ・事実の入口・結論（この回で問う核）を1〜2段落で先に示す。
  4. **本編（原則4章）**: `## 第1章 ...` 〜 `## 第4章 ...`（必要に応じて3〜5章に調整可）。
  5. **おわりに**: `## おわりに` → `今日の話をまとめます。` → 番号付き4項目まとめ（末尾の句点なし可） → 定型クロージング：
     `それでは、本日もお聞きいただき、ありがとうございました。兵庫クリーンラジオ、お別れの時間です。失礼します。`
  6. **参考資料**: 見出しは太字なしの `※参考資料` とし、箇条書きで一次資料・報道・過去回参照（例：`20261115（本配信の過去回）`）・留保注記・壁打ちメモを記載する。

## 4. エージェントの振る舞い（壁打ち・校正・分析時）

- **壁打ちを頼まれたとき**: まず配信者の主張・メモに対して「事実誤認・飛躍・強すぎる断定・不足ソース・想定される反論」を率直に指摘し、そのうえで対比軸や構成の核を複数提案する。
- **過去回・年表との接続**: 新規テーマを扱う際は、`hyogo/analysis/` の棚卸しレポート（`202609-11_inventory_and_evolution.md`）、統合時系列年表＆周辺事件整理ノート（`2024-2026_timeline_and_incidents.md`）、および直近月の原稿を確認し、関連する過去回や重複論点・時系列上の位置づけがあれば明示する。
- **AI臭さの排除**: 「〜と言えるのではないでしょうか」「〜が浮き彫りになりました」などの定型AI表現を避け、短文を交えた自然な語り口（です・ます基調、要所で簡潔な言い切り）に整える。
- **名誉毀損・法的リスク点検**: ドラフト出力時は、断定表現・伝聞の扱い・私的領域への踏み込みがないかを点検し、注意点があれば台本外で簡潔に知らせる。
